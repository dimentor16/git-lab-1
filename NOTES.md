Під час виконання роботи я створив окрему гілку feature/build, щоб ізолювати зміни системи збірки від основної гілки main.
Гілка в Git — це незалежна лінія розробки, яка дозволяє вносити зміни, не впливаючи на стабільний код у main.
Команда git merge об'єднує історії двох гілок і створює новий merge-коміт, зберігаючи обидві лінії розробки в графі.
Команда git rebase переносить коміти моєї гілки поверх останнього коміту main, переписуючи історію та змінюючи хеші комітів.
Я зробив висновок, що merge краще використовувати для вже опублікованих гілок, а rebase — для локального впорядкування історії перед пушем.
Під час роботи я навмисно створив конфлікт у файлі BUILD.md і навчився вручну розв'язувати його, повністю видаляючи службові позначки конфлікту з файлу.
